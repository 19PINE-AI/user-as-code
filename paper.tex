\begin{abstract}
Current personalization in AI agents primarily relies on Retrieval-Augmented Generation (RAG) over unstructured text, structured knowledge graphs, or flat fact stores. While effective for basic recall, these ``Bag of Facts'' approaches struggle with the specific challenges of user memory: resolving conflicting information, managing temporal dependencies, and enforcing logical constraints. This paper introduces \textbf{User as Code}, a paradigm where an agent's understanding of a user is maintained as a \textbf{modular, version-controlled software project}. Our core observation is that \textbf{code is the only representation format that unifies readability and verifiability in a single medium}: the same Python that stores a user's passport expiry date can also express---and execute---the assertion that the expiry is too close to a booked flight. We propose a two-phase architecture: (1)~append-only fact extraction that never loses information, and (2)~periodic structuring into typed Python dataclasses. This enables a \textbf{generate-verify-review loop} where the coding agent generates Python constraints, the interpreter verifies computation deterministically, and pre-computed alerts are surfaced in a compact manifest. We evaluate on LOCOMO, LongMemEval, and a novel Active Service benchmark against Mem0, A-MEM, and full-context baselines. On a fully symmetric evaluation where all systems run on the same data with the same Gemini~3 Flash backbone---5-conversation LOCOMO (300 QAs), a 200-question stratified sample of LongMemEval, and a new 100-case analytical-inference benchmark---User as Code achieves 78.0\% on LOCOMO (94.7\% of the full-context upper bound) and 84.5\% on LongMemEval, outperforming three recent SOTA systems we reimplement on the same backbone (MemMachine 75.3\%/--, Hindsight 70.0\%/70.5\%, EverMemOS 55.0\%/79.5\% on LOCOMO/LME) plus the Mem0 and A-MEM baselines by 21--60pp. The new analytical-inference benchmark exposes a structural divide: retrieval-based memory (Mem0 6\%, MemMachine 43\%) collapses on aggregate questions because top-$k$ retrieval cannot enumerate, while code-executable representations (UaC~v5 99\%, Full Context with a Python REPL 100\%) scale with $N$. We instrument every Gemini call and report token cost: UaC's one-time structuring pays back after \texttildelow3 repeated queries against the same user state, after which it is an order of magnitude cheaper than re-loading raw records every query. Replacing Gemini~3 Flash with GPT-5.4 throughout the UaC pipeline preserves performance (80.8\% on a 2-conversation LOCOMO subset, within 2pp of the Gemini run). Active Service alert detection reaches 100\%---a capability where existing memory systems have no equivalent mechanism.
\end{abstract}
