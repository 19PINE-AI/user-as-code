\begin{abstract}
Current personalization in AI agents primarily relies on Retrieval-Augmented Generation (RAG) over unstructured text, knowledge graphs, or flat fact stores. While effective for basic recall, these ``Bag of Facts'' approaches struggle with the specific challenges of user memory: resolving conflicting information, managing temporal dependencies, and enforcing logical constraints. This paper introduces \textbf{User as Code}, a paradigm where an agent's understanding of a user is maintained as a \textbf{modular, version-controlled software project}. Our core observation is that \textbf{code unifies readability and verifiability in a single medium}: the same Python that stores a user's passport expiry date can also express---and execute---the assertion that the expiry is too close to a booked flight. We propose a two-phase architecture: (1)~append-only fact extraction that never loses information, and (2)~periodic structuring into typed Python dataclasses, enabling a \textbf{generate-verify-review loop} where the coding agent generates Python constraints, the interpreter verifies them deterministically, and pre-computed alerts surface in a compact manifest.

Evaluated symmetrically on the same Gemini~3 Flash backbone, User as Code reaches 78.0\% on a 5-conversation LOCOMO subset (300 QAs; 94.7\% of the 82.3\% full-context upper bound, with the gap to upper bound not statistically significant under McNemar, $p{=}0.12$) and 84.5\% on a 200-question stratified LongMemEval sample. Against three recent SOTA systems we reimplement on the same backbone---MemMachine, Hindsight, EverMemOS---UaC leads on LOCOMO and ties MemMachine on LongMemEval ($84.0\%$ vs.\ $84.5\%$, McNemar $p{=}1.0$); the lead over Hindsight, A-MEM, and Mem0 is significant ($p<0.01$). Representations matter most where the answer is not a single contiguous span: UaC's lead is decisive on LOCOMO and analytical inference, narrower on span-style LongMemEval questions. A new 100-case analytical-inference benchmark exposes a structural divide: retrieval-based memory (Mem0 6\%, MemMachine 43\%) collapses on aggregate questions because top-$k$ retrieval cannot enumerate, while code-executable representations (UaC~v5 99\%, Full Context with a Python REPL 100\%) scale with $N$. Instrumenting every Gemini call shows UaC's one-time structuring pays back after $\sim$3 repeated queries against the same user state; amortized over 100 queries it costs $\sim$15$\times$ less than reloading raw records every query.
